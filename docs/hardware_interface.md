# 乒乓球视觉智能裁判系统 · 硬件与外设对接规范

**文档定位**：面向负责相机搭建、工控机/边缘盒子部署、物理按键扩展、外接数显计分牌或投屏显示的硬件与嵌入式同学。  
**核心原则**：算法核心层（`core/`）保持**零深度学习框架依赖（纯 CPU 极速运行）**，与视觉模型解耦，支持模块化部署与硬控干预。

## 2. 视频采集与相机标定要求

### 2.1 推荐相机参数
| 参数项 | 最低要求 | 推荐配置 | 说明 |
| :--- | :--- | :--- | :--- |
| **分辨率** | 1280×720 (720p) | 1920×1080 (1080p) | 保证小球在画面中有至少 15~25px 直径 |
| **帧率 (FPS)** | 60 fps | **120 fps** | 乒乓球时速极快，120fps 能清晰抓捕击球反折瞬间 |
| **曝光时间** | ≤ 1/500 秒 | **≤ 1/1000 秒 (短曝光)** | 必须压制高速运动拖影，避免球拉成半透明长条 |
| **镜头类型** | 广角无畸变定焦 | 焦距 4mm~6mm | 确保覆盖整张球台两侧各外延 50cm 区域 |

### 2.2 机位安装几何
* **安装位置**：建议固定于球网侧上方 45°~60° 俯视机位，或端线后上方高角度俯视。
* **球台预设坐标（`core/geometry.py`）**：
  系统支持通过四角像素坐标完成单应性矩阵（Homography）标定，将 2D 像素映射为真实球台 $(X, Y)$ 物理厘米。
  * 标准球台物理尺寸：长 274.0 cm，宽 152.5 cm，球网物理居中 $X = 137.0\text{ cm}$。
  * 如更换机位，只需测量球台 4 个角点像素并在 `core/geometry.py` 中新增 `preset`。

## 3. 硬件控制与物理输入对接（GPIO / 串口）

在真实比赛中，机器可能发生遮挡漏判。系统设计了**硬件带外优先介入通道**，硬件按键事件可直接注入状态机：

### 3.1 实体物理按键定义
| 按键编码 / 宏定义 | 触发动作 | 状态机行为 | 适用硬件外设 |
| :--- | :--- | :--- | :--- |
| `KEY_LET` | 擦网重发球 / 干扰重发 | 回滚当前分，状态重置为 `SERVING` | 裁判席大红蘑菇头按钮 |
| `KEY_FAULT_A` | 判罚 A 半台违例 | 直接判 B 得分，切入 `POINT_SCORED` | 裁判实体按键 |
| `KEY_FAULT_B` | 判罚 B 半台违例 | 直接判 A 得分，切入 `POINT_SCORED` | 裁判实体按键 |
| `KEY_ADD_A` | A 得分手工加 1 | 强行修正比分 `Score_A += 1` | 旋钮 / 计分拨轮 |
| `KEY_ADD_B` | B 得分手工加 1 | 强行修正比分 `Score_B += 1` | 旋钮 / 计分拨轮 |
| `KEY_RESET_MATCH`| 整场比赛清零 | 比分重置为 0:0，回到 `WAITING_SERVE` | 硬件重置拨码开关 |

### 3.2 外部物理事件代码调用接口
硬件监听线程（如读取树莓派/微控制器的 GPIO 或串口按键后），直接调用状态机方法：
```python
from core.state_machine import TableTennisStateMachine, MatchRules

# 1. 初始化状态机
sm = TableTennisStateMachine(MatchRules())

# 2. 硬件按钮按下回调（例如裁判按下重发球 LET 按钮）
def on_gpio_let_pressed(timestamp_s: float):
    decisions = sm.manual_let(timestamp_s=timestamp_s, reason="裁判实体按键重发")
    for d in decisions:
        print("硬件介入生效:", d.describe())

# 3. 硬件按钮按下回调（例如手工给 A 加 1 分）
def on_gpio_score_a_pressed(timestamp_s: float):
    sm.points["A"] += 1
    print(f"当前修正比分: {sm.points['A']} : {sm.points['B']}")
```

## 4. 实时比分输出协议（面向数显屏 / LED 大屏 / 串口）

状态机在每一帧步进（`tick`）或更新（`update`）后，均可导出标准的 JSON 数据包，供硬件解析并驱动外设显示。

### 4.1 输出数据包格式 (JSON Payload)
```json
{
  "timestamp_s": 12.350,
  "score": {
    "A": 3,
    "B": 2
  },
  "server": "A",
  "state": "RALLY",
  "game_over": false,
  "last_decision": {
    "kind": "POINT",
    "text": "P1(A) 得分 [DOUBLE_BOUNCE] 球在 B 半台双跳",
    "rule": "DOUBLE_BOUNCE",
    "time": 12.280
  }
}
```

### 4.2 串口传输示例 (UART 协议帧)
若硬件采用单片机（STM32 / ESP32）驱动数码管，推荐简化为定长十六进制帧：
```text
帧头 (0xAA 0x55) | A得分 (1 Byte) | B得分 (1 Byte) | 发球方 (0:A / 1:B) | 状态码 (1 Byte) | 校验和 (1 Byte) | 帧尾 (0x0D 0x0A)
```

## 5. 边缘算力开销与部署建议

| 硬件平台 | 部署配置 | 运行模式 | 预期帧率 | 资源占用 |
| :--- | :--- | :--- | :--- | :--- |
| **x86 迷你工控机 / 笔记本** (如 i5/i7) | CPU 跑状态机 + 4060/核显跑 YOLO | 端到端视频/摄像头 | 150~250 FPS | 显存 2GB，CPU 15% |
| **瑞芯微 RK3588 边缘盒子** | NPU 跑 YOLO11n (INT8 RKNN) + CPU 跑核心状态机 | 嵌入式一体机部署 | 90~120 FPS | 内存占用 < 300MB |
| **Jetson Orin Nano (8GB)** | TensorRT 跑 YOLO11n + CPU 跑状态机 | 工业现场部署 | 100~140 FPS | 功耗仅 15W |
| **树莓派 4B/5 / 纯 CPU 单板** | 接收外部推流的 JSONL 观测，纯跑状态机与比分 | 裁判核心/显示驱动盒 | **10,000+ FPS** | CPU 仅 3%，内存 50MB |

> **关键工程优势**：本项目的 `core/` 目录**纯纯零深度学习依赖**（不依赖 PyTorch、CUDA、TensorFlow）。在资源极度受限的小工控板上，只需 `python run_referee.py --jsonl ...` 即可全速运行，极易移植与长期无故障看门狗守护。
